# Shiny App-Packages

Source: https://mjfrigaard.github.io/shiny-app-pkgs/

## What makes it an app-package

A **Shiny project** is `app.R` (+ optional `R/`, `www/`). An **app-package** is an
installable R package containing the app. Required:

1. `DESCRIPTION` with all 7 mandatory fields:
   `Package`, `Version`, `License`, `Description`, `Title`, `Author`, `Maintainer`
   (Author/Maintainer via `utils::person()`), plus `Encoding: UTF-8` and
   `Config/roxygen2/markdown: TRUE`.
2. `.Rproj` with build fields (enables IDE Build pane):
   ```
   BuildType: Package
   PackageUseDevtools: Yes
   PackageInstallArgs: --no-multiarch --with-keep.source
   PackageRoxygenize: rd,collate,namespace
   ```
3. Code as functions in `R/`. Neither file alone suffices — both needed.

## The three dev habits

| Habit | Function | Shortcut |
|---|---|---|
| Load | `devtools::load_all()` | Ctrl/Cmd+Shift+L |
| Document | `devtools::document()` | Ctrl/Cmd+Shift+D |
| Install | `devtools::install()` | Ctrl/Cmd+Shift+B |

- `load_all()` replaces "Run App" — call after every change to `R/`.
- Lost track of state? Run load → document → install in order.
- Never list `devtools` itself as a dependency; depend on what you actually use.

## Standard layout

```
pkg/
├── DESCRIPTION
├── NAMESPACE            # generated by roxygen2 — never edit by hand
├── R/
│   ├── mod_<name>.R     # UI + server module pair per file
│   ├── <utility>.R      # one function per file, named after the function
│   ├── launch_app.R
│   ├── <pkgname>-package.R  # use_package_doc()
│   └── zzz.R            # .onAttach() startup messages if needed
├── data/                # .rda files from use_data()
├── data-raw/            # raw data + processing script (.Rbuildignored)
├── inst/www/            # static assets served via addResourcePath()
├── man/                 # generated .Rd files
├── tests/testthat/
├── app.R                # .Rbuildignored launcher
└── vignettes/, README.Rmd, NEWS.md
```

Naming: rename catch-all `utils.R` files to `<function>.R` so test files map 1:1
(`test-<function>.R`). Module functions: `mod_<thing>_ui(id)` / `mod_<thing>_server(id)`,
both exported, documented with `@seealso` linking each pair and `@family` grouping.

## Key recipes

**Standalone app function** (exported, returns shiny.appobj — testable):
```r
#' @export
launch_app <- function() {
  shiny::shinyApp(ui = movies_ui, server = movies_server)
}
```

**`app.R` at root** (add with `usethis::use_build_ignore("app.R")`; needs pkgload in Imports):
```r
pkgload::load_all(".")
launch_app()
```
Put `@importFrom pkgload load_all` in the package doc (`use_package_doc()`).

**Package data**: `use_data_raw("name")` → put raw CSV in `data-raw/` → processing script
ends with `usethis::use_data(stones, overwrite = TRUE)` → document with roxygen2 in `R/data.R`.

**Static resources** (packages have no auto-served `www/`):
```r
# in UI function
shiny::addResourcePath('www', system.file('www', package = 'pkg'))
img(src = 'www/shiny.png')   # note: no 'inst/' prefix
```

**Dependencies**: add with `usethis::use_package("pkg")` → then either
`pkg::fun()` everywhere (preferred), `@importFrom pkg fun` (operators/special cases),
or `@import pkg` only for heavy use like `shiny`. Exports need `@export`.
`devtools::document()` updates NAMESPACE but NOT DESCRIPTION.

**roxygen2 minimums**: every function gets title/description, `@param` for each arg,
`@return`, `@examples` (wrap app-launching examples in `if (interactive())`).
Use `@inheritParams source_fn` (roxygen2 ≥8 supports filtering: `@inheritParams f id`
or `-param`). Tag values start on the same line as the tag. Check staleness before
commit with `roxygen2::needs_roxygenize('.')`.

## Converting an existing Shiny project

1. `usethis::create_package("path/pkgname")` (or add DESCRIPTION to existing dir)
2. Move code into functions under `R/`: modules + utility fns + standalone app fn
3. Replace `library()` calls with explicit namespacing or imports
4. Add `.Rproj` build fields; terminate R session so IDE re-reads it
5. `load_all()` until clean → document → install
6. Data → `data-raw/`; `www/` → `inst/www/` + `addResourcePath()`
7. `use_git()`, `use_testthat(3)`, `use_mit_license()`, `use_readme_rmd()`

## Framework decision table

| Framework | Is a package? | Deps | When |
|---|---|---|---|
| Plain app-package | Yes | minimal | Default choice. Full control, least magic |
| golem | Yes | heavy runtime dep | Team standardization wanted; `dev/` scripts guide setup→deploy; `add_*`/`use_*` scaffolding, `with_test` arg creates tests alongside new modules; `mod_`/`fct_`/`utils_` prefixes |
| leprechaun | Yes | zero runtime deps | golem-style scaffolding without shipping golem to prod; `use_*` bundles JS/Sass into `inst/` |
| rhino | **No** | renv + box + node.js | Only when team wants box modules & app structure over package tooling; no DESCRIPTION/NAMESPACE |

## Quality gates (non-CRAN apps)

Skip full `devtools::check()` when not CRAN-bound; use:
- `goodpractice::gp(path = ".")` — targeted advice (URL/BugReports fields, long lines,
  whole-package imports). Filter checks: `gp(checks = 'no_import_package_as_a_whole')`
- `lintr` for issues, `styler::style_pkg()` for formatting
- `attachment::att_amend_desc()` to rescan code and update DESCRIPTION deps

## AGENTS.md snippet for Shiny projects

```markdown
## This is a Shiny app-package
- Dev loop: `devtools::load_all()` after any R/ change; document + install before commit.
- Modules live in R/mod_*.R as ui/server pairs; utilities one-function-per-file.
- Static assets in inst/www/, served via addResourcePath(system.file(...)).
- Tests mirror R/: tests/testthat/test-<file>.R. Unit (testthat) + integration
  (testServer) + system (shinytest2). BDD describe()/it() with Gherkin descriptions.
- Debugging: browser() inside observe(), never bare in server code.
- Quality: goodpractice::gp(), lintr, styler instead of full R CMD check.
```
